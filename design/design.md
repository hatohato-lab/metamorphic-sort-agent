# metamorphic-sort-agent 設計メモ

この文書は「なぜこの設計にしたか」の記録です。使い方は README、概念入門は 01_airepo の `00_入門_…` ／ `00_詳説_…` を参照。

## 実証する設計パターン
**メタモルフィック（性質ベース）オラクル**。
「期待出力(golden)」を一切持たずに、正しい実装なら必ず満たす**関係(metamorphic relation)**だけで
正しさを判定する。テストオラクル問題（正解が分からない／用意できない状況）への別解。

## なぜ「メタモルフィック」を選んだか（他方式との比較）★この repo の肝・正直な位置づけ
- 正直に言うと、**ソートには本当は正解（golden）が作れます**（標準の sorted() と比べればよい）。
- それでも**あえて golden を使わず、性質だけで判定**しているのは、**「正解を用意できない問題」でも正しさを確かめる手法（メタモルフィック）を、分かりやすい題材で実証する**ためです。
- ソートを選んだ理由：満たすべき性質（順序・要素保存・冪等・置換不変・長さ保存）が**直感的で見やすい**から、手法の教材として最適。
- 対比：js-to-ts は差分テスト、py2to3 は静的 golden（どちらも正解が作れる）。本 repo は「**正解が作れない場合**」のための列を担当する（だから sort で “golden を封印” して見せる）。

## 判定する関係（MR）
- MR1 順序保存: 出力は非減少列。
- MR2 多重集合保存: 出力は入力の並べ替え（要素と個数が一致）。
- MR3 長さ保存: len 一致。
- MR4 冪等: sort(sort(x)) == sort(x)。
- MR5 置換不変: 入力をシャッフルしても結果不変。

## なぜ信頼できるか（オラクル自己検証）
`--selftest` で、既知バグ実装を捕まえられることを示す:
- broken_reverse（降順）→ MR1 で FAIL。
- broken_dedup（重複除去）→ MR2/MR3 で FAIL。
- broken_truncate（要素脱落）→ MR3/MR2 で FAIL。
正例 reference は全 MR PASS。＝「正しいものを通し、誤りを捕まえる」物差しであることを先に証明する。

## 入力生成
種固定の乱数（再現可能）。値域を狭めて重複を多発させ、空・単一要素・既ソート・逆順の端も含める。

## 一般化（golden が作りにくい対象でこそ活きる）
MR は対象ごとに設計する:
- 検索 … 要素を足すと結果は単調に増える
- 最短経路 … 全辺の重みへ一様加算しても経路の順位は不変
- 文字列正規化 … 冪等（二度かけても同じ）
- エンコード／デコード … 往復で元に戻る（round-trip）

## 既知の限界
- MR は必要条件であって十分条件ではない（全 MR を満たしても稀に誤りは残りうる）。golden オラクルと補完関係。
- 乱数入力の網羅は有限。種・件数・値域で弁別力が決まる。
